# HELPVET — сайт, заявки, Telegram и кабинет клиники

Это комплект для VPS, а не GitHub Pages. Сайт, API и кабинет работают в одном приложении. Сервер не требуется собирать вручную: готовый `app.jar` включён в архив.

## Что работает

- Публичная одностраничная мобильная версия с текущим дизайном.
- Форма: имя, телефон, направление и комментарий, согласие на обработку данных.
- Заявка сначала сохраняется в файловой базе, затем ставится в очередь Telegram.
- Сбой Telegram не удаляет заявку. Очередь повторяет отправку автоматически.
- `/admin.html`: вход администратора, список заявок, отметка «Обработана», состояние Telegram и ручной повтор уведомления.
- Изменение цен, адреса, телефона, графика и текста политики через кабинет.
- Логин, пароль и Telegram-настройки не находятся в JavaScript.

## Что нужно от вас для запуска

1. VPS с Linux и установленными Docker Engine + Docker Compose.
2. Домен или поддомен, DNS-запись A которого направлена на VPS.
3. Токен вашего Telegram-бота и ID чата, куда посылать заявки. Не присылайте токен в чат: внесите его прямо на сервере.
4. Собственный длинный пароль администратора.

На новом VPS удобно использовать комплект с Caddy: он получает и продлевает HTTPS-сертификат. Домен должен указывать на VPS; порты 80 и 443 должны быть доступны снаружи и свободны. Если на VPS уже есть Nginx и другие сайты, не останавливайте и не заменяйте их: используйте альтернативный вариант ниже или отдельный поддомен с существующим прокси.

Docker: https://docs.docker.com/engine/install/ubuntu/
Caddy HTTPS: https://caddyserver.com/docs/automatic-https

## Вариант 1. Docker + Caddy (готовая конфигурация)

Следующие команды выполняются в терминале **VPS**, не Windows. Самостоятельно они здесь не запускались.

### 1. Загрузите и распакуйте

Через SFTP загрузите архив `helpvet-vps.zip` на VPS. Откройте папку `/opt/helpvet` и распакуйте **содержимое** архива так, чтобы `/opt/helpvet/app.jar`, `/opt/helpvet/compose.yaml` и `/opt/helpvet/deploy/Caddyfile` лежали именно по этим путям. Используйте новую папку; не распаковывайте поверх другого сайта.

Если распаковываете через терминал в новой папке:

```bash
sudo mkdir -p /opt/helpvet
sudo unzip /путь/к/helpvet-vps.zip -d /opt/helpvet
cd /opt/helpvet
```

### 2. Заполните секреты

```bash
sudo cp .env.example .env
sudo chmod 600 .env
sudo nano .env
```

Заполните:

```dotenv
DOMAIN=ваш-домен.ru
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ваш-уникальный-пароль-от-16-символов
TELEGRAM_BOT_TOKEN=токен-вашего-бота
TELEGRAM_CHAT_ID=идентификатор-чата
DATABASE_PASSWORD=
```

`DOMAIN`: только имя домена, без `https://` и `/`. Для пароля используйте латинские буквы, цифры, `_` и `-`; достаточно 24–40 случайных символов. Это избавляет от неоднозначностей формата `.env`. Не оставляйте пример вместо настоящего пароля.

DATABASE_PASSWORD необязателен. Если задаёте его — сделайте это до первого запуска и не меняйте после создания базы без отдельной процедуры смены пароля.

Никогда не загружайте `.env` на GitHub. `.env.example` содержит только пустые поля и может храниться с исходниками.

### 3. Подготовьте Telegram

- Создайте бота через официальный `@BotFather`, если своего бота нет.
- Для личного чата пользователь должен открыть бота и нажать Start.
- Для группы добавьте бота в нужную группу и разрешите ему отправлять сообщения. ID группы обычно отрицательный.
- Внесите токен и правильный chat ID в `.env` на VPS. Все заявки будут отправляться именно в этот чат.
- Если данные ещё не заполнены, сайт всё равно сохраняет заявки; кабинет покажет, что Telegram не настроен. После заполнения `.env` перезапустите контейнер приложения, чтобы обработать очередь.

Документация ботов: https://core.telegram.org/bots

### 4. Запустите

```bash
cd /opt/helpvet
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose logs --tail=80 app
```

`config --quiet` проверяет конфигурацию, не печатая пароли. Не публикуйте вывод команды `docker compose config` без `--quiet`: в нём могут быть секреты.

Публичный сайт: `https://ваш-домен.ru/`
Кабинет: `https://ваш-домен.ru/admin.html`

Порт приложения наружу не открыт. Все посетители проходят через Caddy и HTTPS. В `.env` не устанавливается COOKIE_SECURE=false: в серверном варианте cookie защищена HTTPS.

### 5. Проверьте после запуска

1. Откройте сайт по HTTPS на телефоне.
2. Откройте кабинет и войдите своим логином и паролем.
3. Заполните часы работы, цены и политику обработки данных с реквизитами клиники. Исходные файлы не содержат цен и часов; они не выдуманы.
4. Отправьте одну тестовую заявку через публичную форму. Она должна появиться в кабинете.
5. Убедитесь, что в Telegram пришло сообщение с тем же коротким номером заявки; в кабинете статус должен измениться на «Доставлено». Первичная попытка обычно выполняется в пределах 30 секунд.
6. Отметьте заявку обработанной и проверьте фильтр.
7. Измените одну цену, обновите публичную страницу, убедитесь, что цена обновилась.
8. Перезапустите приложение `sudo docker compose restart app`, затем проверьте, что заявка и цена сохранились.

До выполнения этих шагов фактический запуск на вашем VPS и доставка в ваш Telegram не считаются проверенными.

## Резервная копия

База находится в постоянном Docker-томе `helpvet_data` и сохраняется после перезапуска контейнера. Обновление JAR её не заменяет. Не используйте `docker compose down -v` — этот флаг удаляет том с данными.

Для согласованной копии базы выполните:

```bash
cd /opt/helpvet
sudo bash deploy/backup.sh
```

Скрипт ненадолго остановит приложение, скопирует базу в `backups/ДАТА/` и запустит приложение снова. Скопируйте резервную копию отдельно от VPS и отдельно сохраните `.env`. Копия базы содержит персональные данные заявок.

Не восстанавливайте старую базу поверх новых заявок автоматически. Восстановление требует остановки приложения и проверки, какие обращения будут потеряны.

## Обновление сайта

1. Сделайте резервную копию.
2. Замените `app.jar` новой проверенной версией. Сохраните старый JAR отдельно.
3. Не заменяйте `.env` и том базы.
4. Выполните `sudo docker compose up -d --build app`.
5. Проверьте сайт, кабинет, заявки и логи.

Файлы фронтенда находятся внутри JAR. Изменение исходного `style.css` на диске само по себе не изменит запущенный сайт — нужно пересобрать JAR.

## Вариант 2. Java + существующий Nginx

Если на VPS уже используется Nginx, Caddy не нужен. Понадобится Java 21 и отдельный пользователь `helpvet`. Пример systemd-службы: `deploy/helpvet.service`. Пример проксирования всего сайта: `deploy/nginx.conf`. HTTPS настраивается через существующую конфигурацию Nginx и действующий сертификат вашего домена.

- Приложение слушает только `127.0.0.1:8080`.
- `app.jar`, `.env` и папка `data` располагаются в `/opt/helpvet`.
- Пользователь `helpvet` должен читать JAR и `.env` и иметь доступ на запись только к папке `data`.
- Создайте `data` и выставьте владельца до запуска systemd.
- `.env` для systemd содержит `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и при необходимости `DATABASE_PASSWORD`.
- Не включайте Docker и systemd одновременно для одной и той же базы или порта.
- Пример nginx.conf обслуживает HTTP как основу; до ввода пароля и реальных заявок обязательно настройте HTTPS. Не заменяйте им весь конфиг существующего сервера без проверки.

## Локальная проверка Windows — без сборки

1. Распакуйте весь архив в отдельную папку, например `C:\Programming\Projects\helpvet-test`.
2. Убедитесь, что установлена Java 21 или новее.
3. Дважды нажмите `start-local.cmd`.
4. Задайте пароль администратора от 16 символов. Ввод скрыт — это нормально.
5. После строки `Started HelpVetApplication` откройте http://localhost:8081/ .
6. Кабинет: http://localhost:8081/admin.html . Логин `admin`, пароль — заданный при запуске.
7. Для остановки Ctrl+C в окне запуска.

`.env` для такого запуска не нужен. Telegram отключён намеренно; заявки сохраняются в `local-data` рядом с JAR и будут видны после повторного запуска. Цены и график можно менять в кабинете. Укажите тот же пароль при следующем запуске или задайте новый: пароль не хранится в локальной базе. Не удаляйте `local-data`, если хотите сохранить тестовые заявки.

Если 8081 уже занят, остановите предыдущий экземпляр. Эта проверка доступна только с текущего компьютера; localhost на телефоне ведёт на сам телефон. Для телефона используйте размещённую версию после запуска на VPS.

## Локальная сборка из исходников

Java 21+, Maven 3.6.3+:

```bash
mvn clean verify
```

Готовый JAR: `target/helpvet.jar`. Скрипты `build.sh` и `build.ps1` после успешной сборки копируют его в `app.jar` для Docker.

Для локальной проверки без HTTPS допустимо временно задать `COOKIE_SECURE=false`, `ADMIN_PASSWORD` и запустить JAR, слушающий только 127.0.0.1. Реальные токены для локальных проверок не требуются.

## Что проверено в этом комплекте

Смотрите `VALIDATION.md`. Автотесты используют отдельную тестовую базу и локальную имитацию Telegram; не посылают сообщения реальным людям.

## Ограничения

- Один администратор, один экземпляр приложения, одна файловая база; это намеренно небольшой сайт.
- Telegram может получить повторное уведомление при обрыве связи после доставки. Номер заявки помогает распознать дубль; в базе остаётся одна заявка.
- Автоматического удаления персональных данных нет: клинике нужно определить срок хранения и процедуру удаления до рабочего запуска.
- Выбранная схема — отредактированное изображение. До публикации сверить с оригиналом; изменение адреса в кабинете не перерисовывает схему.
- Обновляйте базовые Docker-образы и зависимости планово. Реальные секреты и базы не входят в архив.
